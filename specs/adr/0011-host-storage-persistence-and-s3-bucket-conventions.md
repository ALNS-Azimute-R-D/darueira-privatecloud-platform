# 11. Host Storage Persistence Architecture and S3 MinIO Bucket Conventions

Date: 2026-08-17

## Status

Accepted

## Context

In containerized multi-plane platforms, default dynamic storage provisioners generate randomized UUID paths (e.g. `/var/snap/microk8s/common/default-storage/pvc-<uuid>`), while temporary storage (`emptyDir`) loses data during pod lifecycle restarts and node reboots.
1. **Host-Level Backup & Auditability**: The developer workstation requires predictable, deterministic filesystem paths on a dedicated partition (`/mnt/FileBuckets01/darueira-platform/data`) to perform transparent incremental backups (`rsync`, `tar`, BorgBackup) without reverse-engineering Kubernetes PVC UUIDs.
2. **Crash Resilience & Data Permanence**: Mission-critical state across Corporate Platform Services (PostgreSQL, MinIO, Forgejo Git, Kafka/Redpanda, RabbitMQ, Nexus, Stalwart Mail), Observability (OpenSearch, Prometheus, Grafana), and Tenant Workloads (ACME PostgreSQL, MongoDB, MinIO) must survive pod restarts, deployments, and cluster downtime.
3. **Structured S3 Object Storage Taxonomy**: Standardize MinIO bucket nomenclature between Corporate Shared Services (`drr-corp-*`) and Tenant Workloads (`drr-tnt-<tenantId>-*`).

## Decision

1. **Dedicated Host Storage Root**:
   - Establish `/mnt/FileBuckets01/darueira-platform/data/` as the single canonical storage hierarchy for all persistent platform and tenant workloads on the host disk partition.
   - Standardize automated directory provisioning and permissions via `scripts/setup_host_storage.sh`.

2. **Custom StorageClass & Static PersistentVolumes**:
   - Register the `darueira-host-storage` StorageClass (`volumeBindingMode: WaitForFirstConsumer`, `reclaimPolicy: Retain`).
   - Define static Kubernetes `PersistentVolume` (PV) resources mapping each component to its dedicated directory on `/mnt/FileBuckets01/darueira-platform/data/`.

3. **S3 MinIO Bucket Standardization & Auto-Provisioning**:
   - **Corporate Shared S3 (`central-minio` in `drr-corpshared-plat`)**:
     - `drr-corp-techdocs`: HTML documentation generated by Backstage / MkDocs.
     - `drr-corp-backups`: Automated database dumps (PostgreSQL, MongoDB, OpenBao).
     - `drr-corp-artifacts`: CI build outputs and release binaries.
     - `drr-corp-mail-storage`: Stalwart Mail Server blob attachments.
     - `drr-corp-logs-archive`: Long-term cold log archives.
   - **Tenant Dedicated S3 (`tenant-minio` in `drr-tnt-<tenantId>`)**:
     - `drr-tnt-<tenantId>-bizapps-documents`: Business documents, PDFs, and invoices.
     - `drr-tnt-<tenantId>-media`: User avatar images and public assets.
     - `drr-tnt-<tenantId>-exports`: Asynchronous report exports (CSV, Excel).
     - `drr-tnt-<tenantId>-backups`: Tenant-level local data snapshots.
   - Attach a lightweight `minio/mc` initialization sidecar to auto-verify and create buckets on startup.

## Consequences

- **Complete Data Permanence**: Zero data loss across pod restarts, image upgrades, and cluster reboots.
- **Instant Host Backups**: Developers can back up all platform databases, Git repositories, and queues with standard host-level filesystem tools.
- **Enterprise Multi-Tenant Object Storage**: Clear, predictable boundary between platform infrastructure and tenant business data.
